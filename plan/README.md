# 青鸾题目推搜与 Agent 实施计划

更新日期：2026-10-30。状态：设计文档；步骤清单尚未作为实施结果验收。

本目录承接根目录 MVP 方案：Codeforces 过题通过官方 API 获取，洛谷过题通过油猴脚本监听并上传；先交付独立推搜页面与规则推荐，再接供应商 API 驱动的 Agent。后端复用现有数据服务，前端暂不复用冒险家协会。小型 CPU 模型作为独立评测选项。

## 已确定的共同约束

- 复用 be 的 Java 17 / Spring Boot、MyBatis、MySQL，以及 newfe 的 Vue 3 / Element Plus / Axios。
- 后端先复用 modules/Adventurers 中的搜索、数据读取及 OJ Mapper，增量服务不依赖任务奖励流程。前端建议新增 newfe/src/features/recommendations 与 /main/problems 入口，复用通用登录和 HTTP；不嵌入 features/adventurers。
- 独立页面是业务和路由独立，默认沿用现有 Vue CLI 工程与发布方式；CPCSearch 和额外前端部署不是必需项。
- 一期基线的搜索、推荐、热门、换题、反馈均为 0 次模型调用；Agent 与语义增强关闭时，不配置供应商密钥、不安装模型运行库也能验收。
- 先直接查询已入库记录并聚合，user_problem_progress 仅作为测量后的优化选项。
- CF 的 API 可访问历史与洛谷监听记录具有不同覆盖范围。记录缺失不等于没做过，做题数量不等于掌握程度。
- 题目库与过题记录分别维护；题目标签复用到所有人的记录，不对每条 AC 重复打标签。
- Agent 的 LLM 使用供应商 API；可选 Embedding 可以评估预训练权重的 CPU 推理或供应商 API，二者不是同一部署决策。
- 预训练 Embedding/重排序可先直接评测；ALS/BPR 等个性化模型通常需拟合本队数据；生成式召回另立实验。任何选项都不是一期前置条件。
- 当前服务器为老款 Xeon 虚拟机、16 个可用 vCPU、约 32.9 GiB 可用内存，未显示 AVX2；仅说明有小模型评测空间，不能承诺兼容性、延迟或并发。资源快照见 03，验证步骤见 14。
- 个人推荐快照独立于 task / task_item / task_assign；本期暂缓任务表单预填，生成推荐不会发布任务或发放奖励。
- 候选必须具有已入库且可核验的 ProblemRef；扩充题库与向量索引分别进行，不让模型虚构目录外题目。
- 保留洛谷脚本采集链路；“扩展 CF 并在 AC 后注入推荐”仍为讨论项，暂不纳入本目录的实现和验收范围。
- 系统提示词和内置 Skill 指导 Agent，权限、工具参数、资源归属和输出类型由 Java 服务强制校验。
- 所有性能指标、效果指标和验收案例都是待执行要求，不代表已经通过。

总体调用和数据契约以 02 为准；选型与服务器快照以 03 为准；CPU 实验细节以 14 为准；操作和验收细节以对应步骤为准。修改公共契约时同步更新引用它的步骤。
