# 步骤 9 · A1 Agent 编排、记忆与边界

更新日期：2026-10-30。状态：二期待实施。返回 [计划目录](README.md)。前置：[11 供应商协议](11-a0-provider-api.md)。下一步：[13 Agent 验收](13-a2-agent-acceptance.md)。

## 1. 目标和模块落点

在现有 Java 后端增加 AssistantService，调用一期搜索、推荐、Hot 和换题能力。使用 MySQL 保存会话与显式偏好，在 features/recommendations 的独立推搜页面增加对话入口，保留完整表单和按钮；不依赖协会前端。

角色边界、题单归属、数据清洗和规则推荐继续由一期服务执行。Agent 不直接创建正式任务、不派发奖励，也不提供通用写作、代码开发或完整题解代写工具。

LLM 通过供应商 API 调用。CPU Embedding 与语义索引均为 E0 可选能力；本步骤不安装本地对话模型，不要求先做向量 RAG 或训练个性化召回模型。

## 2. 一轮请求的执行顺序

1. 从登录态取得业务 user.id，校验会话归属、request_id、内容摘要与会话 version。
2. 创建或读取持久请求控制记录。已完成同内容请求返回原结果，同标识不同内容报冲突。
3. 读取有效会话条件、当前快照、明确偏好和必要的精简训练概况；完整过题集合留在数据库。
4. 组装系统提示词、内置任务说明、固定工具 schema 和本轮数据，调用供应商。
5. 校验动作和参数，生成服务端动作 ID，将动作参数与摘要持久化后再执行。
6. 调用一期 Java Service，业务幂等键由 request_id 与服务端动作 ID 稳定派生。
7. 保存动作结果引用；确需继续决策时才回传必要工具结果并再次调用模型。
8. 在短事务内校验会话版本，保存消息、当前题单引用、请求结果及合法偏好变化。
9. 返回后端认可的卡片/模板，记录调用次数、用量、失败原因和版本。

会话内串行处理有副作用的请求，进行中状态需要数据库可判定的超时/恢复规则。写操作前及最终保存时核对请求归属与版本，超时旧请求不能覆盖新状态。

不要让数据库事务覆盖供应商网络请求。工具直接调用 Java 方法，同样必须执行 Service 内的用户、资源和权限校验，不能依赖只有 HTTP Controller 才执行的检查。

## 3. 条件合并与多轮指代

优先级固定为：本轮明确要求 > 当前会话条件 > 有效长期偏好 > 可见且可编辑的默认值。合并结果回显给用户，后端校验后交给 RecommendationService。

“第三题换简单一些”必须定位当前 slate_id 的第三个有序项，再校验请求修改的范围。没有当前题单、存在多个指代或难度含义不明确时，返回受限澄清，不能任选一份历史题单操作。

“这次只要 CF”更新本会话；“以后默认 CF”才进入明确长期偏好流程。跨平台难度按独立字段表达，不把 CF 数值套入洛谷等级。

## 4. 记忆存储与更新

| 内容 | 存储 | 更新方式 |
| --- | --- | --- |
| 会话条件与当前题单 | assistant_session.state_json / current_slate_id | 受会话版本保护，引用一期不可变题单 |
| 展示消息 | assistant_message | 有序保存，模型上下文只取受限近期内容 |
| 请求与动作状态 | 专用控制记录；可复用消息持久层或用 assistant_request | 用户内唯一 request_id，保存动作计划、摘要、结果和状态 |
| 长期偏好 | assistant_preference | 专用偏好接口或本轮明确表达的受限动作 |
| 阶段目标 | 带 expires_at 的偏好 | 按 Asia/Shanghai 解释期限，过期不参与合并 |
| 做题事实和反馈 | 一期原始表、查询与 recommendation_event | 每次从业务层读取，不用聊天内容改写正式 AC |

建议偏好白名单：preferred_platforms、default_problem_count、preferred_topics、cf_rating_range、luogu_difficulty_range。键和值具有固定类型、范围、来源和版本，不能保存任意“系统指令”。

模型提出偏好变化仍需验证确有本轮明确请求；歧义时澄清，界面展示变更并允许删除/调整。局部“太难”反馈不能自动变成永久低难度偏好。

对于请求控制记录，若沿用消息表无法提供单一唯一请求实体和动作状态，则采用小型 assistant_request 表，包含 user_id、session_id、request_id、body_hash、state、actions_json、result_ref、version/恢复信息。这是有限请求恢复，不建设通用工作流引擎。

## 5. 删除、到期与请求恢复

偏好删除或过期后，条件合并立刻不再使用。删除更新版本和遗忘边界，清理相关缓存及会话中继承的默认值；旧消息或旧题单不能重新恢复该长期偏好。

历史题单保留当时条件用于回看，不等于新的偏好来源。过期训练目标不从会话摘要中自动续期；上下文展示历史内容时标记其非当前状态。

服务中断后，同 request_id 从持久记录恢复：

- 已完成：返回原结果及当前有效性提示。
- 已计划、未完成动作：复用服务端保存的动作和稳定幂等键，不让重新采样产生另一套写操作。
- 业务已提交、动作回执未保存：用同一幂等键查询或重试，取回已有题单/反馈结果。
- 尚无持久动作计划：在剩余许可规则下重新解析，但已完成动作不得再生成。
- 会话版本过期或执行权已转移：标为冲突/失败，不覆盖较新会话；已保存的个人题单仍可按归属查询。

不恢复模型内部推理状态，也不把供应商调用 ID 当成唯一的业务幂等依据。偏好更新、请求完成及会话引用需要一致提交或可核对恢复。

## 6. 提示词、内置 Skill 与工具限制

系统提示词描述推题职责、支持范围、数据来源、约束优先级和默认不剧透。内置 Skill 使用项目自有版本化说明，例如 search.md、recommend.md、replace.md，描述参数提取、澄清和调用步骤。

这些文件放在二期后端资源目录，由应用选择加载，不接受用户上传的“新 Skill”覆盖。Skill 不携带脚本执行能力，不动态安装插件，不决定最终权限。

提示词与 Skill 不能保证消除提示注入，应用需要独立校验工具、身份和输出。[OWASP 官方说明](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)

| 边界 | 后端落实方式 |
| --- | --- |
| 身份 | 从登录态注入当前用户；忽略或拒绝模型提出的其他 userId |
| 资源 | 会话、快照、反馈、偏好逐项核验归属 |
| 工具 | 固定注册表与当轮允许集合；无任意 SQL、Shell、文件读取、URL 请求或管理代理 |
| 参数 | 平台、词表、数量、难度、字段、偏好类型与期限严格校验 |
| 文本 | 用户、题面、标题、工具结果、历史消息均作为数据，不升级为系统指令 |
| 输出 | 题目和 URL 来自后端，理由代码/澄清字段受限，任意模型正文不直接展示 |
| 上下文 | 只发送必要概况，不发送密钥、完整过题明细或其他队员私人资料 |
| 预算 | 执行步骤 11 的调用、时间、频率与额度限制 |

题目标题等数据库文本按普通文本渲染，链接按已核验平台标识生成。模型可以建议条件，但不能生成未入库题目冒充真实搜索结果。

范围判断可能误判，因此验收既检查越界，也检查正常业务被误拒绝的情况。不把“使用了 JSON schema”描述成语义安全保证。

## 7. RAG 和记忆的技术边界

本阶段通过 SQL 和业务工具检索题目、过题概况与热门事实，足以支持基于事实的响应。向量库不是记忆的必需组件，长期偏好也不需要 Embedding。

例如“推荐 5 道 CF 二分题”由 LLM 提取结构化条件，再调用标签查询和规则推荐，已经形成基于事实的闭环。E0 的题目向量用于找相似内容，不保存用户身份、偏好、会话执行状态或正式 AC。

若 E0 独立验收后由推荐服务内部增加语义候选，Agent 仍调用同一工具；硬过滤、可核验题目目录、请求预算和题单持久化继续由 Java 执行。相似度和模型猜测不能写为永久偏好或掌握程度，语义服务关闭不影响结构化工具。

若以后需要从大量训练复盘文本检索内容，再评估用户隔离的语义索引，并补齐删除同步。该能力不改变 MySQL 中的身份、偏好与过题事实来源。

## 8. 前端、交付与验收

在独立推搜页增加对话和偏好查看/修改/删除入口，继续保留表单。用户看到已采用条件、当前题单、可恢复请求状态及清晰的能力范围；不加载协会任务表单，也不向浏览器下发模型权重或 Key。

单题反馈沿用一期按钮和事件接口；本期不额外开放反馈写入工具。用户先标记“已做过”后，Agent 换题读取同一有效排除状态，不能把一句自然语言陈述直接写成正式 AC。

交付 AssistantService、固定工具适配、提示词和内置说明、会话/偏好/请求持久化、推荐模块内的对话与偏好 UI、幂等恢复及边界检查。独立对话入口不代表另建前端工程。

- [ ] 普通自然语言请求调用一期服务，不另写一套推荐算法。
- [ ] 当前快照指代、会话条件和长期偏好优先级正确。
- [ ] 删除/到期后旧消息不会重新激活默认偏好。
- [ ] 重试、崩溃恢复和并发版本冲突不产生重复写入或覆盖新状态。
- [ ] 模型不能改变主体、读取他人题单、调用未知工具或发布正式任务。
- [ ] 任意模型正文不会透传为成功业务结果，事实说明来自后端。
- [ ] 供应商故障或关闭 Agent 时，表单推搜与正式协会业务可用。
- [ ] 无向量库或 Embedding 配置时，条件解析、多轮指代、偏好和 SQL 工具闭环完整可用。

本步骤只完成实现与必要检查，完整边界、误拒绝、费用及运行验收在步骤 13 独立进行。
