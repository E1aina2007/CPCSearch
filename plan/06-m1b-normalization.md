# 步骤 3 · M1B 规范化清洗与题库补齐

更新日期：2026-10-30。状态：待实施。返回 [计划目录](README.md)。前置：[04 审计](04-m0-data-audit.md)、[05 接入契约](05-m1a-ingestion.md)。下一步：[07 搜索与统计](07-m1c-search-and-profile.md)。

## 1. 目标与输入

把已核验来源记录和题目目录整理成推荐可查询的规范标识、标签及有效性信息。保留原始表，不为了做推荐批量覆盖历史排名或任务结算结果。

输入包括来源字段映射、账号归属、题库样本、标签字典、时间语义及采集覆盖。先处理可信试点，再扩展范围；异常数据保留定位信息，不静默猜测。

## 2. 题目目录与过题记录分开处理

| 数据链 | 工作 | 产出 |
| --- | --- | --- |
| CF 题库 | 复用已有目录，可对接官方 problemset.problems 更新元数据 | 来源题号、标题、rating、标签及有效性 |
| 洛谷题库 | 核验已有管线及标签字典，补充缺少的题目元数据 | pid、标题、独立难度、规范标签及来源 |
| 提交记录 | 验证账号归属、来源键、结果、题号和时间 | 可关联题目的有效提交读取口径 |
| 同题映射 | 核对训练赛或跨平台的可靠对应关系 | 经核验 problem_alias |

CF 官方 problemset.problems 可返回题目与统计元数据。[官方说明](https://codeforces.com/apiHelp/methods#problemset.problems)

洛谷油猴能上传过题不代表同时提供完备题目库。若题库暂时不足，先在已核验目录范围内推荐，并明确候选范围；不把有过题记录的题目集合当作全部可推荐题。

第一版不要求完整题面、题解或 AI 批量标注，题目目录继续使用 cf_official_problems 与 luogu_all_problems。

可推荐目录允许包含本队尚无人 AC 的题目；只有来源引用、元数据和状态经过核验才能进入候选。过题表缺目录的有效题号仍参与已做题排除，不能因为缺标签就丢掉过题事实。模型或外部文本提到的目录外题目不得直接成为推荐卡片。

## 3. 规范化规则

1. 业务身份使用 user.id；归属冲突隔离，改绑时核验历史记录是否仍属于本人。
2. 提交按 M0 确定的来源键去重，保留合法团队成员归属；重复 AC 与重复提交分开处理。
3. CF 成功取有效 verdict=OK，洛谷取经来源映射确认的 is_pass=1；缺失、未知和中间态另列。
4. 常规题号转为结构化 ProblemRef，保留来源 key 与 canonical key，B1/B2 不拆坏。
5. 无可靠别名时 canonical key 就是自身；训练赛映射不能只靠同名，Easy/Hard 等版本保持区分。
6. CF rating 与洛谷 difficulty 独立归一；未知不编码成简单题，不建立未经验证的数值等价换算。
7. 标签在题目层规范化，记录原始值、来源、状态和词表版本。
8. 平台提交时间、接收时间分别保留；统一范围转换和显示时区，补传不制造当日新增。

cf_team_problems.official_contest_id 的字段名不足以证明其中存的是比赛编号或完整题号，要依据实际样本和来源证据解析。

## 4. 标签与别名产物

problem_tag 表达来源题目与 tag_code 的多对多关系。词表使用版本化配置，先覆盖可靠的一级算法类别和同义词。例如 dp、dynamic programming、动态规划映射到统一代码。

洛谷标签若存数值，必须关联字典再解释；不能用字符串包含关系匹配数值标签。未识别标签计入质量报告，不转换成模型猜测的细类。

problem_alias 只对已核验映射建立有效关联，保存证据与版本。源题不得同时指向多个有效 canonical key；写入时检查循环和相互冲突。无别名的题不需要人为填充大量自映射行。

画像统计从现有记录按需查询，user_problem_progress 不在本步骤强制创建。即使暂不持久化画像，也要在本步骤固定去重和时间口径，供搜索、推荐和热门共享。

若以后采用模型辅助打标签，预测标签必须带来源和待核验状态，不覆盖可靠官方标签，也不直接作为严格细类约束。E0 的 Embedding 相似度不构成题目别名或算法标签的核验证据。

## 5. 清洗运行方式

- 新增或复用 CleaningService，用稳定键分页读取必要字段，按小批事务更新标签和映射。
- 在 clean_run 或兼容运行记录中保存输入边界、规则版本、检查点、成功/隔离数量与状态。
- 重跑相同输入和规则结果一致；规则更新能定位受影响题目与用户。
- 初次回填使用只启用清洗的运行配置，明确禁止其他周常派发、奖励和贡献定时任务随之执行。
- 多实例通过数据库协调同一任务；控制批量、并发与连接占用，不长时间锁住在线大表。
- 有可靠变更游标时重叠读取并周期核对；仅有 creation_time 时不能据此发现旧提交重判。
- 异常样本保留定位键和隔离原因，可用清洗运行记录及报告承载，不先建设通用数据平台。

判题、账号归属、题号别名或标签修正后，下次直接查询应反映新结果；如果以后增加缓存或汇总表，再同步实现版本失效和受影响范围重算。

## 7. 可选语义实验的数据准备

仅在决定开展 [14 E0](14-e0-cpu-model-evaluation.md) 时，选少量具有可靠题号与来源的中英文文本样本。先核对来源、许可、语言、题面/题解区分，记录内容 hash 与更新时间；题面可用独立扩展存储，暂不改变两张题库的基础契约。

文本清理保留数学符号、输入输出和关键约束，不能为了长度静默删掉决定算法的条件。超长题面、只有标题或只有标签的样本分别标识；仅用标题/标签的实验不能被描述为已验证完整题意语义检索。

本步骤的必要交付不包含模型下载、向量回填或训练。先完成试点清洗并推进功能，正文补齐与模型实验有单独状态和预算。

## 8. 验收与退出条件

- [ ] 同一批数据重跑结果一致，失败后能从有效检查点继续。
- [ ] 原始来源与隔离样本仍可定位，没有以删除原记录掩盖冲突。
- [ ] CF B1/B2、洛谷 pid、已核验训练赛映射和有效链接均正确。
- [ ] 同名不同题、Easy/Hard 版本、未核验跨平台疑似同题没有误合并。
- [ ] 标签覆盖比例有明确分母，粗标签未被扩写成未经证实的细类。
- [ ] 历史补传使用原提交时间；未知难度不进入严格难度候选。
- [ ] 全部已知历史的去重口径可由后续查询复用，不依赖必须先建聚合表。
- [ ] 清洗运行未调用正式任务派发、奖励或贡献结算。
- [ ] 未 AC 的有效目录题可以成为候选，缺目录的有效历史 AC 不会从排除集合消失。

可靠试点达到上述条件后进入共享搜索开发；其余待核验数据继续隔离，缺少完整题面不阻塞本步骤结束。
