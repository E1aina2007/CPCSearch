# 步骤 8 · A0 供应商 API 接入

更新日期：2026-10-30。状态：二期待实施。返回 [计划目录](README.md)。前置：[10 一期验收通过](10-m3-mvp-acceptance.md)。下一步：[12 Agent 与记忆](12-a1-agent-and-memory.md)。

## 1. 目标和范围

在原应用中增加可关闭的 LLM ModelClient 和受限业务动作协议。Agent 的对话模型在供应商侧推理，本地运行 Java 编排；本步骤无需对话权重、GPU 或自训练推荐模型。已有服务器可评估小型 CPU Embedding，不改变这里的 LLM 部署选择。

前置输入为已验收的一期业务 Service、现有 HttpClient5 / Jackson、可用供应商账户，以及固定的条件理解样本。语义增强关闭时，基础表单搜索与推荐仍为 0 次模型调用；E0 语义实验不作为 A0 前置，开启后的调用统计单独记录。

## 2. 供应商与配置

先评估 Qwen 的工具调用 API，Plus 系列可以作为候选之一；实际模型 ID、地域、协议和支持参数按接入时官方文档与账户及固定样本确认。备选 DeepSeek 见 [03 技术选型](03-technology-options.md)，本步骤只实现一个供应商。

模型可返回工具名称及参数，应用负责执行；工具定义不是数据库执行授权。[Qwen 官方说明](https://help.aliyun.com/zh/model-studio/qwen-function-calling)

| 配置 | 要求 |
| --- | --- |
| Agent 开关 | 默认关闭；关闭时无需模型 Key，不建立供应商启动依赖 |
| 模型与 API 地址 | 后端部署配置固定，不接受用户或模型提供任意地址 |
| API Key | 仅后端私有配置，不写入前端、文档、日志或模型上下文 |
| 连接与请求超时 | 小于剩余总预算，区分连接失败和供应商处理超时 |
| 输入、输出上限 | 限制消息、工具结果及输出长度 |
| 用户频率与额度 | 服务端校验；无关请求和重试也消耗实际预算 |
| 版本 | 记录模型标识、协议适配、提示词、Skill 和工具 schema 版本 |

供应商模型别名可能变化；记录实际可获得的响应模型信息，不把浮动别名当成永远固定的模型版本。

Agent 开关与 E0 的语义增强开关独立，LLM Key/模型配置与 Embedding 配置分开。供应商提供聊天 API 不代表同一模型或端点能生成 Embedding；不在本步骤顺带接入向量服务。

## 3. ModelClient 职责

复用 HttpClient5 的连接池和 Jackson，封装请求/响应映射、超时、异常、用量及调用状态。业务工具由 AssistantService 选择和执行，ModelClient 不直接查询业务表或持有任意管理能力。

初期采用普通请求/响应。网络重试仅针对可重试错误并计入剩余预算，不因模型超时重新执行已经完成的业务动作。模型调用期间不持有数据库长事务。

常见路径为一次模型解析 → 一次或少量 Java 工具 → 后端卡片和模板。只有确需继续决策才追加模型调用，不固定增加第二次润色请求。

工具调用只是将自然语言转换为受限业务动作。推荐策略、已做题排除和题单存储继续由一期服务完成；模型无需看到完整过题明细，也不负责生成目录外候选题号。

## 4. 受限动作与返回协议

| 动作/工具 | 可接收内容 | Java 的处理 |
| --- | --- | --- |
| searchProblems | 题号/标题、平台、规范标签、难度、分页 | 调用一期共享搜索 |
| recommendProblems | 数量、组配额、平台、主题、各平台难度 | 合并条件后调用规则推荐 |
| getHotProblems | 7d/30d、平台、分页 | 读取统一 Hot 口径 |
| replaceProblem | 本人题单引用、已校验题目位置/key、局部约束 | 调用一期换题 |
| CLARIFY | 受支持的缺失字段或歧义代码 | 渲染固定业务问题 |
| OUT_OF_SCOPE | 固定范围外代码 | 渲染能力范围说明 |
| UPDATE_PREFERENCE | 本人白名单偏好键、类型化值和期限 | 在 A1 由专门入口校验显式变更 |

工具参数使用固定 schema 和范围，拒绝额外身份字段、SQL、任意 URL、任意排序字段和未知动作。即使供应商支持严格结构输出，也必须再次校验参数、身份和业务约束。

首次调用可同时做业务路由，不另接分类模型。不支持强制工具或 schema 参数的具体型号，需要在适配层按已验证能力处理；不能假设所有“兼容接口”行为相同。

服务端成功返回类型限于题目列表、题单、热门、业务澄清、偏好更新及范围外说明。模型返回普通无关正文时不直接透传，也不自动退化成通用聊天。

## 5. 调用预算和降级

初始配置为每轮最多 3 次模型调用、5 次工具调用，总处理预算 20 秒，包含网络重试和工具执行。先实测再调整，不将配置值描述成供应商时延承诺。

现有 Axios 默认超时 10 秒。仅 Agent 请求单独设置例如 25 秒，并核对代理超时；其他接口保持现有配置。调用失败时优先返回已经完成且有效的业务结果，否则提示使用表单或稍后重试。

对话入口将在独立推荐前端模块中增加，不依赖协会页面或任务表单。若未来工具内部启用 E0，其耗时也受本轮总预算限制，Embedding 调用、费用和失败分类单独统计，不冒充 LLM 调用次数。

若 Redis 被用于额度控制，Redis 不可用时暂停模型入口或使用经验证的替代限额机制，不能直接失去额度限制；一期数据服务保持独立运行。

## 6. 交付与验收

交付 ModelClient、单供应商适配、开关/配置、动作 DTO/schema、错误处理、预算记录和最小调用演练结果。本步骤可使用受控工具桩验证协议；真实多轮记忆与权限在 A1 完成。

- [ ] 关闭 Agent、无 Key 或供应商不可达时，一期启动与功能不受影响。
- [ ] 对固定样本返回可解析动作，数量、标签、平台和难度可验证。
- [ ] 无效 JSON、未知工具、额外身份字段和不支持参数得到受控处理。
- [ ] 密钥不进入前端、模型上下文或日志，API 地址不能被用户改写。
- [ ] 超时、重试、调用次数及用量均计入同一轮预算。
- [ ] 工具桩返回真实结构，普通模型正文不会作为成功业务结果直接展示。
- [ ] 记录实际费用和时延，未测指标不填成已通过。

本步骤完成只证明协议接入，不代表 Agent 的记忆、范围控制、故障恢复或完整推题链路已验收。
