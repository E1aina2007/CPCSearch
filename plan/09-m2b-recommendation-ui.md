# 步骤 6 · M2B 独立推搜前端

更新日期：2026-10-30。状态：待实施。返回 [计划目录](README.md)。前置：[08 推搜业务接口](08-m2a-recommendation.md)。下一步：[10 一期验收](10-m3-mvp-acceptance.md)。

## 1. 目标与落点

交付独立的题目搜索与推荐入口，覆盖搜索、条件推荐、热门、换题、反馈和历史。暂不复用冒险家协会页面、布局、任务表单或任务详情组件，也不把任务预填作为一期要求。

默认选择现有 newfe 工程内的新功能模块，继续使用 Vue 3、Element Plus、Axios 和通用登录能力。独立指业务页面和路由独立，不默认增加第二套前端工程、构建链和部署。若以后确需单独站点，再按 [03 选型](03-technology-options.md) 评估。

建议位置与入口如下，均为待创建方案：

~~~text
newfe/src/features/recommendations/
  screens/       推搜页面、本人题单历史
  components/    条件表单、题目卡片、题单、反馈
  api/           推搜接口封装
~~~

建议路由 /main/problems，作为 /main 下独立功能入口，沿用通用应用布局和登录守卫，不作为 /main/adventurers 的子路由。组件数量按实际交互决定，不为每个展示字段拆文件。CPCSearch 不作为本步骤必需落点。

## 2. 页面与交互

| 区域 | 用户操作 | 展示要求 |
| --- | --- | --- |
| 条件区 | 选平台、题型、各平台难度、题数、巩固/探索分配 | 默认值可见可改，回显实际条件；难度挑战与新题型探索区分 |
| 搜索 | 搜题号、标题、算法标签；选择是否排除已做题 | 稳定分页、来源链接、独立平台难度和可靠标签 |
| 推荐 | 生成个人题单 | 有序题目、组别、模板理由、同步时间与数据覆盖 |
| 调整 | 换指定题、改条件重新生成 | 绑定正确快照，保留题失效时提示整体刷新 |
| 热门 | 查看近 7/30 天现役成员新增过题热度 | 去重人数、时间和已收集样本范围 |
| 历史 | 查看本人旧题单 | 保留原顺序和原条件，另显示当前已做或失效状态 |
| 反馈 | 已做过、不感兴趣、太难、太简单及撤销 | 自报仅影响本人推荐，不能展示为官方 AC |

一期不放置尚未实现的聊天或语义搜索占位入口。题号、标题、算法标签是基础搜索能力，不能把任意自然语言描述标为已支持的 AI 搜索。

空结果、某组缺题、执行预算用尽、绑定冲突、采集历史不完整与系统故障使用不同提示。清洗版本、内部分数、模型协议等诊断信息不进入常规选题流程。

候选来自可核验题目目录，允许包含本队尚无人做过的题；没有元数据的目录外题不由前端临时拼接卡片或跳转地址。

## 3. 通用能力复用与接口契约

- [HTTP 封装](../newfe/src/core/api/http.js)：复用 /api 基址、Bearer 认证、刷新与错误处理；调用路径不要重复 /api。
- [路由](../newfe/src/core/router/index.js)：接入通用登录、角色校验和导航，新增独立入口；实际允许角色与后端策略一致。
- [前端依赖](../newfe/package.json)：沿用现有 Vue CLI、Element Plus 和 Axios，不顺带迁移到 Vite。
- 推搜接口契约以 [02 架构设计](02-architecture.md) 为准；前端 API 放入新功能目录，不从协会 tasks.js 导入管理端选题操作。

保留 /api/adventurers 的拟定后端路径，不意味着依赖协会前端。普通队员走新增的成员接口；共享后端搜索与旧 /api/admin/tasks 调用方之间的兼容由服务层处理，不能为了新页面放开整个管理路径。

前端路由和按钮控制只改善交互，个人题单、事件、会话与偏好权限仍由服务端逐项校验。不得从 localStorage 中的角色或客户端 userId 推导写入授权。

## 4. 请求状态与异常恢复

生成题单、换题与反馈携带稳定的 request_id/event_id。相同操作重试沿用标识；修改条件后发起新操作使用新标识。服务端承担并发幂等，不能只依赖按钮禁用。

使用请求序号或取消过时读取，防止慢响应覆盖较新的题单；取消前端请求不等于撤销服务端已经完成的写入。超时后用相同业务标识重试取回结果，避免重复生成。

题目标题按普通文本渲染，跳转地址来自服务端核验的来源引用。历史快照保持原内容，当前 AC 状态以最新业务查询为准；“已做过”反馈与平台采集 AC 的说明分开。

普通 HTTP 足够完成一期交互，无需 SSE 或新增 WebSocket。二期 Agent 请求的独立超时见步骤 11，不全局放宽全部接口。

## 5. 后续扩展边界

二期在本模块内增加对话、会话恢复和偏好管理，继续保留表单与按钮。Agent 关闭时基础页面完整可用。

E0 若通过，再为语义检索增加明确入口与降级提示；是否调用 Embedding 由后端配置及能力决定，不在浏览器下载模型或保存供应商 Key。实验未通过前不把语义能力加入一期验收。

正式任务表单预填与发布集成暂缓。当前只要求推搜不调用任务创建、派发或奖励；对确实修改的共享后端能力做旧调用方回归。未来若恢复任务衔接，需要独立明确入口、引用格式转换和权限验收。

本步骤不扩展油猴脚本，不实现 OJ 页面中的 AC 后推荐展示。

## 6. 交付与验收

交付独立推搜页面、API 封装、必要组件、路由导航和真实后端交互记录。

- [ ] 有权队员能从独立入口完成搜索 → 推荐 → 换题 → 反馈 → 历史查看。
- [ ] 页面不依赖 AdventurersPage、CreateTaskForm 或 TaskDetailModal，不挂在协会子路由下。
- [ ] 通用登录、刷新与错误处理正常，未开放管理端接口给普通用户。
- [ ] 平台难度、实际条件、缺题原因与来源覆盖清楚可见。
- [ ] 重试和乱序返回不覆盖新结果，不重复创建业务记录。
- [ ] 自报排除、撤销与真实 AC 的展示、作用保持区别。
- [ ] CF B1/B2 等来源引用和跳转正确，不在前端构造未核验题目。
- [ ] 生成、换题与反馈不创建 task/task_assign，也不触发奖励。
- [ ] Agent 与语义增强关闭、无模型 Key 和本地模型时，一期页面完整可用。
- [ ] 通用前端改动及共享后端改动的实际受影响调用方完成回归。

界面验收使用真实后端契约。前端构建或静态截图不能替代权限、幂等与入库演练；本步骤不声称完成正式任务集成。
