# 项目及全链路介绍

更新日期：2026-10-30。状态：设计方案。返回 [计划目录](README.md)。

## 1. 项目目标与用户

青鸾服务 ICPC 集训队，已有账号绑定、过题记录、排名和冒险家协会任务能力。本次增加个人题目搜索、巩固与探索题单、现役队员热门题，以及后续的自然语言推题入口。

队员在独立推搜页面通过表单找题、生成题单、换题和反馈。前端默认沿用 newfe 工程的登录、HTTP 和通用组件，新建推荐功能目录与路由；不复用冒险家协会页面、布局和任务表单。正式任务衔接暂缓，推搜不赋予发布、派发或奖励权限。

一期以 Java/SQL 解决结构化找题、巩固、难度挑战和新题型探索，基线零模型调用。二期让 Agent 通过供应商 LLM API 理解自然语言、维护会话条件，并调用同一套业务能力。CPU/API Embedding 属于可选增强，不是 Agent 或一期的前置条件。

从产品组成看，是现有一个后端、一个前端，加已有洛谷采集脚本；已有 CF 官方 API 采集任务继续运行。脚本是数据来源的一部分，尚不承担推荐展示；CF 脚本扩展与 AC 后注入推荐的讨论不进入本计划。

## 2. 现有数据与两条采集链

| --- | --- | --- | --- |

## 3. 数据进入推荐前发生什么

首先按登录用户的业务 user.id 解析有效 OJ 绑定。user 与 oj_account 中的绑定若冲突，先隔离影响范围，不能随意择一归属。然后按平台确认提交身份、当前可用判题结果、题号和提交时间。

对同一用户同一规范题目，重复 AC 不增加去重过题数。相同题目的多平台引用只有在别名证据可靠时合并；不同难度版本、仅同名题不直接合并。来源题号仍保留用于展示、跳转和既有后端调用方兼容。

标签统一在题目层维护。官方粗标签只能支持相应粒度的推荐；没有可靠细类标签时，不把普通 dp 自动扩写成树形 DP、数位 DP 等已证实分类。

查询时可临时得到以下概况，不先建设常驻画像服务：

| 统计 | 用途 | 解释边界 |
| --- | --- | --- |
| 全部已知历史中的去重 AC 集合 | 排除已做题及已核验同题 | 只能保证当前入库范围 |
| 每类题的去重过题数 | 选择巩固方向与探索候选 | 不是能力评分；多标签计数不能直接相加成总题数 |
| 近期新增与最后练习时间 | 判断近期练习和复习需求 | 新增先计算全部已知历史最早 AC 提交时间 |
| 各平台、各题型难度分布 | 提供可编辑的难度建议 | CF rating 与洛谷等级不等值换算 |
| 来源覆盖、标签匹配与更新时间 | 控制推荐结论的强度 | 洛谷零记录不能被解释为从未学习 |

若原始数据仅包含 AC，就不计算真实通过率、失败次数或解题耗时。提交创建时间也不等于用户最终看到 AC 的时刻。

## 4. 普通搜索与推荐链路

普通搜索由表单提交题号、标题、平台、规范标签、各平台难度和是否排除已做题。后端进行身份与条件校验，通过共享查询返回稳定分页结果，全程不调用模型。

推荐流程如下：

1. 取得用户显示确认的约束，默认题量 5 道，可设置 1～10 道。
2. 查询有效绑定、全部已知历史过题、题型统计及有效个人反馈。
3. 从题库取候选，执行平台、主题、难度、有效性、已做题和个人排除条件。
4. 分别选择巩固题与探索题，再在允许范围内做标签组合去重和难度编排。
5. 不足时继续分页到满足数量、真实耗尽或预算用尽；不会擅自放宽条件。
6. 返回前复查新入库 AC，保存条件、顺序、依据和数据时间，展示模板理由。

候选取自已入库且身份、来源可核验的题目目录，不限于本队已经有人做过的题。目录中尚无人 AC 的新题也可推荐；目录外题须先由独立采集/补齐流程核验入库。基础推荐使用的是标签内容匹配、难度规则和行为统计，没有依赖模型才能完成的必要环节。

例如用户希望 3 道二分巩固题和 2 道新题型入门题：巩固部分采用熟悉标签与合适难度；探索部分由用户选择或教练维护的少量前置/相邻题型配置产生。新题型不默认提高难度。

默认 3:2 仅是可调试行比例，不是已验证的最佳策略。用户限定只练 DP 时，探索也必须位于其允许的主题范围；没有细类数据时返回限制说明。

Hot 题单按当前现役用户、近 7/30 天的已知新增过题统计不同用户人数，记录统一截止时间。它反映已收集样本的热度，不代表全站热门。

## 5. 反馈、后续 AC 与个人题单

题单是不可变快照。换第 3 题时生成带父快照引用的新题单，不改写历史结果。记录曝光、点击、太难、太简单、不感兴趣、已做过等反馈，并支持规定的撤销操作。

“已做过”自报只形成个人排除项；真正 AC 由既有采集链路入库后参与过题统计。自报不能直接提高排名、热门人数或正式任务进度。

用户完成题目 → CF 下次同步或洛谷脚本上传 → 同一清洗/查询口径生效 → 下次推荐排除这道题。历史题单保留原内容，读取时可附加当前已过题状态。

个人题单不进入 task、task_item、task_assign。正式任务表单衔接属于以后单独安排的功能；本期只检查共享后端改动没有破坏原任务契约，不建设协会前端集成。

## 6. Agent 参与时的完整链路

~~~mermaid
sequenceDiagram
    participant U as 队员
    participant A as AssistantService
    participant D as MySQL
    participant M as 供应商模型 API
    participant R as 一期推搜 Service
    U->>A: 自然语言请求 + 会话版本
    A->>D: 校验归属，读取条件、偏好和当前题单
    A->>M: 精简上下文 + 固定工具定义
    M-->>A: 请求动作及结构化参数
    A->>A: 参数、身份、工具及预算校验
    A->>R: 调用搜索 / 推荐 / 热门 / 换题
    R->>D: 查询事实并保存幂等业务结果
    R-->>A: 真实题目、约束、依据、结果引用
    A->>D: 短事务保存会话与请求结果
    A-->>U: 后端卡片与受限说明
~~~

常见请求一次模型调用解析动作后即可返回模板结果；只有确需继续处理才追加模型调用。模型失败时，表单推荐保持可用。

Agent 的记忆保存会话条件、题单引用和本人明确表达的偏好。实时过题事实从数据库读取，不把完整提交历史放进模型上下文，也不把对话当作正式 AC 证据。

系统提示词和内置 Skill 描述业务范围；Java 工具注册、资源归属、参数和响应类型校验执行边界。Agent 不获得任意 SQL、外部 URL 请求、任务发布或奖励工具。

## 7. 可选的模型辅助推荐链路

若 E0 评测通过，可增加“题目文本 → 预训练 Embedding → 相似题候选 → 统一过滤和规则编排”的支路。其用途是改善题意检索，不替代标签、真实 AC、权限或难度约束。

题目文本可在后台批量编码；以已有题为种子找相似题时，可直接复用已存向量或预计算相似题 ID，新 AC 本身不要求触发一次模型推理。输入新的自然语言语义查询时才需要生成查询向量；模型不可用时明确降级到结构化搜索。这里只定义后端能力，不引入浏览器推荐注入。

小题库先用 Java 内存相似度计算或预计算结果，不强制新增向量数据库。Agent 的自然语言条件解析与语义检索是两个能力：解析“5 道 CF 二分题”并查询标签，无需先做 Embedding。预训练权重也不等于已经学会本队个人偏好。

服务器已提供的资源快照允许开展 CPU 小模型试验；运行库兼容性、中文/英文效果、长题面处理和在线延迟尚未验证。详见 [03 选型](03-technology-options.md) 与 [14 可选评测](14-e0-cpu-model-evaluation.md)。
